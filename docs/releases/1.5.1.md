# DepthWall 1.5.1

Fixes the AOD module making the phone look rooted to apps that hide from Magisk.

Installs as a normal update over 1.5.0 (same signing key). Library and settings are kept.

## The AOD module no longer loads into other apps

The 1.5.0 module turned on crDroid's "wallpapers on AOD" flag with an overlay on the Android framework. Android loads framework overlays into the starting process of every app, before Magisk's DenyList or Shamiko can hide anything, and crDroid's built-in hiding does not cover it. Apps that check for root, such as DigiYatra, could see that overlay coming from the Magisk module folder and reported the phone as rooted.

crDroid already sets that flag to true itself, so the overlay was never needed there. The 1.5.1 module ships no overlay: it only installs DepthWall as a system app, which no other app loads, so the DenyList hides it as usual. AOD should behave the same.

To update:
1. Install DepthWall 1.5.1 over 1.5.0.
2. Rebuild the module from the APK you installed: `python3 tools/build_aod_module.py app/build/outputs/apk/release/app-release.apk`.
3. Flash `artifacts/DepthWall-AOD-module.zip` in Magisk or KernelSU over the old module, then reboot. The old framework overlay is removed with it. Your wallpaper-on-AOD choice is kept.
4. In DepthWall, open **Settings → Always-on display → Set up & check AOD**. **ROM shows wallpapers on AOD** should be on.

On a ROM other than crDroid where that line stays off, rebuild with `--systemui-overlay`. It adds an overlay that only SystemUI loads, but it still leaves a few traces of the module (a Magisk mount on `/product/overlay` and a cache file in `/data/resource-cache`), so use it only when needed.

## Checking what apps can see

Open the apps you care about, then run `tools/integrity_report.sh SERIAL artifacts/integrity` on your computer. It checks DigiYatra, Claude, DigiLocker, Google Play services and the Play Store; add other package names after the folder to check them too. Magisk asks once to allow root for Shell. In `app-mappings.txt`, the "system paths served from /data" list under each process should be empty. A line there is a file from some Magisk module that the app can see, whichever module it comes from.

Neither the no-overlay module nor `--systemui-overlay` has been run on the emulator or the phone yet. If **ROM shows wallpapers on AOD** stays off, include the report's `overlays.txt` in the bug report.

## Not fixed by this release

Some apps decide on Google Play Integrity alone. On Android 13 and later its device verdict needs a locked bootloader and a certified manufacturer image, so an unlocked crDroid phone only gets the basic verdict, with or without the module. The Claude app has checked this at sign-in since late October 2026; use claude.ai in the browser instead.
